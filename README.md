# Kanbanly

Канбан-сервис с конструктором досок: доска собирается из блоков (колонки, измерения, поля, виджеты шапки, анатомия карточки, палитра, типографика), и любую собранную доску можно сохранить как шаблон. Пресеты — обычные JSON-файлы, в коде нет ни одной ветки под конкретный пресет.

## Запуск

```bash
make up          # Docker Compose: api, web, db, mailhog
```

Приложение: <http://localhost:8080>, почта для разработки: <http://localhost:8025>. Перед первым запуском `make up` создаёт `.env` из `.env.example`; для боевого развёртывания задайте свой `KANBANLY_SECRET_KEY` и `KANBANLY_COOKIE_SECURE=true`.

### Без Docker

Нужны `uv` и Node.js 22. Один процесс отдаёт и API, и собранный фронт, данные — во временной SQLite:

```bash
cd frontend && npm ci && npm run build
cd ../backend && uv sync && uv run python scripts/e2e_server.py
```

В Windows PowerShell 5.1 оператора `&&` нет, команды выполняются построчно:

```powershell
cd frontend
npm ci
npm run build
cd ..\backend
uv sync
uv run python scripts/e2e_server.py
```

Откройте <http://127.0.0.1:8123>. Письма со ссылкой сброса пароля в этом режиме лежат файлами во временном каталоге сервера.

## Развёртывание на сервере

Нужен Linux-сервер с Docker Compose v2, домен с A-записью на этот сервер и открытые порты 80 и 443.

```bash
git clone https://github.com/MazurBogdan7/Kanbanly.git
cd Kanbanly
cp .env.production.example .env
nano .env   # заполнить все значения; ключ и пароль: openssl rand -hex 32
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Миграции применяются при старте `api`, HTTPS-сертификат Caddy получает сам. С заглушками вместо секретов приложение в `prod` не запустится.

### Сервер, где уже есть nginx и другие сайты

Если порты 80 и 443 уже заняты nginx, Caddy не нужен: Kanbanly слушает только `127.0.0.1:8090`, а домен отдаёт nginx сервера.

```bash
docker compose -f docker-compose.yml -f docker-compose.nginx.yml up -d --build
cp deploy/nginx-kanbanly.conf /etc/nginx/sites-available/kanbanly   # вписать свой домен
ln -s /etc/nginx/sites-available/kanbanly /etc/nginx/sites-enabled/kanbanly
nginx -t && systemctl reload nginx
certbot --nginx -d kanban.example.com
```

Своего домена пока нет — используйте `kanban.<IP-через-дефисы>.sslip.io` (например `kanban.203-0-113-7.sslip.io`): это имя само указывает на IP сервера, и certbot выдаст для него настоящий сертификат. Остальные сайты на сервере это не затрагивает. Обновление: `git pull` и та же команда `docker compose ... up -d --build`.

### База данных

- **На этом же сервере** (по умолчанию): в `.env` оставьте `COMPOSE_PROFILES=localdb`, Postgres поднимется в контейнере `db`.
- **Внешняя** (управляемый Postgres у хостинга или другой сервер): удалите строку `COMPOSE_PROFILES=localdb` и укажите адрес в `KANBANLY_DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/DBNAME?ssl=require`. Контейнер `db` тогда не запускается.

Переехать позже можно без потерь: сделайте копию (`deploy/backup-db.sh`), восстановите её во внешнюю базу (`gunzip -c копия.sql.gz | psql "адрес"`) и поменяйте `.env`.

### Резервные копии

```bash
crontab -e
30 3 * * * cd /path/to/Kanbanly && sh deploy/backup-db.sh >> var/backup.log 2>&1
```

Копии складываются в `var/db-backups`, хранятся 14 дней. Регулярно уносите их с сервера. Кроме того, каждый пользователь может скачать свои данные сам: доску — в меню доски (JSON или таблица CSV для Excel), проект — в меню проекта, всё сразу — в профиле, раздел «Данные и бэкапы».

### Администратор

Первый зарегистрированный на сервере пользователь становится администратором. Пункт «Админка» в меню показывает пользователей, снимает блокировку после неудачных входов, отключает аккаунты, выдаёт права администратора, завершает сеансы, удаляет пользователей и закрывает открытую регистрацию. В разделе «Доски пользователей» администратор скачивает бэкап любой доски, а в списке пользователей — бэкап всего аккаунта; такой файл восстанавливается через «Импорт из файла». Каждая выгрузка записывается в журнал безопасности.

После 20 неверных паролей подряд аккаунт блокируется. Снять блокировку можно в админке, сбросом пароля по почте или из консоли сервера:

```bash
docker compose exec api .venv/bin/python -m app.cli unlock user@example.com
docker compose exec api .venv/bin/python -m app.cli make-admin you@example.com
```

### Импорт доски из файла

Доску можно взять из файла прямо при создании проекта («Новый проект» → «Доска из файла») или в проекте («Импорт из файла»). Подходят:

- **CSV** из Excel, Google Таблиц, Trello или выгрузки Kanbanly (разделитель `;`, `,` или табуляция, кодировка UTF-8 или Windows-1251). Колонки доски берутся из столбца «Статус» или «Колонка», карточки — из «Название», «Описание» и «Срок». Остальные столбцы становятся измерениями (если значения повторяются, например «Приоритет») или полями.
- **JSON-шаблон Kanbanly** — проходит шаги мастера, можно сменить тему.
- **JSON-бэкап Kanbanly** доски или проекта — доски переносятся со всеми карточками, комментариями, чек-листами, тегами и цветами.
- **JSON-массив задач** вида `[{"title": "...", "status": "...", "description": "..."}]`.

### Документы и теги проекта

На странице проекта есть раздел «Документы»: ТЗ, диздок, пояснительная записка, таблицы и картинки (до 25 МБ на файл). Файлы хранятся в базе приложения. PDF, Word (.docx), Excel (.xlsx), Markdown, текст и картинки открываются для просмотра прямо в браузере. Редактировать файл нельзя, можно загрузить новую версию, прежние остаются в истории. У документа есть описание, теги и комментарии с автором и датой.

Теги проекта общие для всех досок и документов: цвет у каждого свой. Карточкам можно задать цвет, и текст на ней автоматически становится чёрным или белым, чтобы читался.

### Команда

Владелец проекта приглашает участников на странице проекта, раздел «Участники»: по email или нику (ник задаётся в профиле) и с ролью «редактор» или «читатель». Зарегистрированному пользователю приглашение приходит прямо в приложение: «Профиль» → «Приглашения», с кнопками «Принять» и «Отклонить»; число новых приглашений видно в меню. Отклонённое приглашение владелец может отправить снова. Тому, кто ещё не зарегистрирован, уходит письмо со ссылкой (если настроена почта), а ссылку можно скопировать и отправить самому.

У каждой задачи можно выбрать исполнителя из участников проекта: он виден на карточке и попадает в выгрузку CSV. Если участник уходит из проекта, его задачи остаются без исполнителя. Изменения других участников появляются на открытой доске в течение 5 секунд без перезагрузки.

Обновление: `git pull`, затем та же команда `docker compose ... up -d --build`. Логи: `docker compose -f docker-compose.yml -f docker-compose.prod.yml logs -f api`.

## Тесты

| Команда | Что делает |
|---|---|
| `make test` | линтеры, типы, backend, frontend, e2e |
| `make test-backend` | pytest с покрытием (SQLite) |
| `make test-postgres` | те же тесты на встроенном PostgreSQL (без Docker) |
| `make test-frontend` | Vitest с покрытием |
| `make test-e2e` | сборка фронта и Playwright: сценарии, эталон ZIF, axe, производительность, снимки |

Без `make` команды запускаются напрямую, см. [Makefile](Makefile). Lighthouse: `npm run lighthouse` при запущенном `scripts/e2e_server.py`. Проверка миграций на чистой базе: `uv run python scripts/pg.py verify`.

После изменения Pydantic-моделей выполните `make schemas`: обновятся `docs/schemas/*.schema.json`, `frontend/openapi.json` и TS-типы.
