# Принятые решения

Требование было неоднозначным или конфликтовало с другим — здесь выбранный вариант и причина.

## Данные и API

1. **Конфигурация доски редактируется одним запросом** `PUT /boards/{id}/config`, а не CRUD на каждую колонку и значение. Конструктор работает с черновиком, undo/redo и кнопкой «Применить»; атомарная запись всего черновика проще и не оставляет доску в промежуточном состоянии. Отдельный CRUD есть у представлений и всего, что внутри карточки.
2. **Движок и API используют локальные ключи**, карточка в ответе содержит `column: "done"` и `values: {"epic": ["core"]}`. Так один компонент рендерит доску, превью и шаблон.
3. **Роли измерений вычисляются из раскладки** (см. ARCHITECTURE). Поле `roles` в шаблоне — входной формат, при экспорте оно заполняется вычисленными ролями.
4. **`ordered: true` в файле ZIF** — сокращение: нормализуется в `type: "ordered_select"`. Файл импортируется без правок.
5. **Заголовок и панель действий в шапке неявные**: в ZIF их нет в `widgets`, а в прототипе они есть. Если виджетов `title`/`actions` в списке нет, они показываются сверху; добавленные явно сортируются и выключаются.
6. **Тип измерения `user`** пока хранит значения как именованный список: аватары рисуются по ним. Привязка к участникам проекта появится вместе с приглашениями (этап 2 продукта).
7. **If-Match необязателен.** Клиент всегда его передаёт; без заголовка запрос проходит, чтобы API оставался удобен скриптам. Перемещение карточки версией не защищено: конфликт порядка отдельно даёт `409 stale_position`.
8. **Корзина**: ручного «очистить сейчас» нет; срок 30 дней соблюдает фоновая задача, она запускается раз в час.
9. **`POST /export/backup`** добавлен к указанному в ТЗ `GET`: пароль шифрования нельзя передавать в URL. Шифрование требует весь документ в памяти, поэтому зашифрованный экспорт не потоковый.
10. **Пароль бэкапа при импорте** передаётся заголовком `X-Backup-Password`, а тело запроса — сам файл.
11. **«Заменить существующие»** перемещает заменяемое в корзину, а не удаляет: вместе с автоснимком это двойная страховка. Сопоставление по исходному id, затем по имени, потому что id пересоздаются при каждом импорте.
12. **В бэкап попадают проекты, которыми пользователь владеет.** Проекты, где он только участник, принадлежат другому аккаунту.
13. **Сброс из шапки возвращает и карточки примеров** (как «Сброс» в прототипе), текущие карточки уходят в корзину. Сброс из конструктора возвращает только настройки.
14. **Миграции JSON**: версий пока одна, цепочка проверена тестом на синтетических мигрантах. При выпуске v2 нужно добавить мигрант и файл старой версии.
15. **Текст, который не примет PostgreSQL** (NUL, одиночные суррогаты), отвергается на входе с 422. SQLite такое хранит, поэтому ошибка была видна только на реальной базе.

## Безопасность

16. **«Письма в лог» против «email и токены не пишутся в логи».** Победил запрет: в dev письмо уходит в MailHog или файлом в `var/dev-mail` (в `.gitignore`), но не в логи.
17. **Rate limit в памяти процесса**, API запускается одним воркером. Для нескольких воркеров нужен общий бэкенд с тем же интерфейсом `RateLimiter`.
18. **Сообщения об ошибке входа одинаковы** для неверного пароля и неизвестного email, время выровнено проверкой фиктивного хэша. Регистрация на занятый email честно возвращает 409: иначе пришлось бы подтверждать адрес письмом до входа.
19. **Сырой HTML в Markdown не поддерживается**: он экранируется до DOMPurify. Изображения в Markdown отключены: загрузка чужой картинки раскрывает факт просмотра.
20. **`style-src` содержит `unsafe-inline`.** Этого требуют Radix и переменные темы; ТЗ запрещает его только для скриптов. Произвольного CSS из JSON нет: значения проходят через валидаторы цвета, URL и белый список шрифтов.
21. **Регулярные выражения в полях** проверяются на вложенные квантификаторы, длина шаблона ограничена. Эвристика закрывает типовой ReDoS, но не доказывает его отсутствие; длина проверяемого текста ограничена 20 000 символов.
22. **ApiToken** заложен моделью, выпуска токенов нет: в сценариях они не участвуют. Приглашения в проект реализованы (п. 36).

## Интерфейс

23. **Приглушение «Готово» и WCAG AA конфликтуют.** Шаблон ZIF задаёт `opacity: 0.65`, но при такой прозрачности текст опускается ниже 4.5:1, а ТЗ требует 0 нарушений axe. Решение: поверхность карточки приглушается как задано, а текст — только до границы читаемости (`readableOpacity`, считается автоматически для любой темы). В ZIF текст в «Готово» чуть ярче прототипа.
24. **Другие отступления ZIF от прототипа ради доступности:** текст пустой колонки использует `text-muted` вместо тусклого `muted-strong`; цвет кнопки «Сброс» усиливается до AA автоматически.
25. **Подписи отличаются от прототипа по ТЗ:** «+ Карточка» вместо «+ Задача», «Все: Веха» вместо «Все вехи». Склонять произвольные названия измерений нельзя без поля в шаблоне, а файл ZIF менять запрещено. Подвал берётся из `footer_note` шаблона, он короче текста прототипа.
26. **Порог эталонного теста — 3% различающихся пикселей** при допуске 60 по сумме каналов. Текущее расхождение: 1,2% (десктоп) и 1,3% (390 px), остаток — перечисленные выше подписи. Сравнивается доска без оболочки приложения: тулбар в прототипе отсутствует.
27. **«+ карточка» внизу колонки появляется при наведении или фокусе** и всегда видна на сенсорных экранах. Иначе колонка стала бы выше эталона.
28. **Виртуализация.** ТЗ называет виртуализацию колонок; использован `content-visibility: auto` вместо оконного рендера: совместим с dnd-kit и сохраняет все карточки в DOM для поиска браузером. Замер на 1000 карточках укладывается в требования (долгая задача рендера около 150 мс, перетаскивание до 310 мс), поэтому оконный рендер не понадобился.
29. **Редактор карточки** следует настройке шаблона (`editor.type`): по умолчанию drawer, в ZIF — модалка, как в прототипе. Раздел «Экраны» ТЗ называет drawer, раздел 5.2 разрешает выбор; выбор шаблона важнее.
30. **Календарь и таймлайн** реализованы как виды доски. Календарь раскладывает карточки по сроку (`due_date`), таймлайн — по упорядоченному измерению: по полю `group_by` представления или по первому измерению типа `ordered_select`.
31. **Загрузка файлов во вложения** не реализована, вложения — ссылки `https`. Файлы потребуют отдельного хранилища, раздуют бэкапы (они должны оставаться переносимыми между серверами) и откроют новую поверхность атаки: подмена типа файла, выполнение в браузере. Сначала нужно решение, где хранить файлы.
32. **TypeScript 5.9**, а не 7: на него ещё не обновились `typescript-eslint` и `openapi-typescript`.
33. **shadcn/ui как основа**: компоненты написаны в том же подходе поверх Radix, но в `components/ui/index.tsx`, без генератора.

## Окружение проверки

35. **Базовые снимки зависят от платформы:** шрифты рендерятся по-разному, поэтому снимки в `tests/visual/__screenshots__` сделаны под Windows и лежат по подкаталогам платформ. CI запускает e2e с `--ignore-snapshots`, пока на Linux не сгенерированы свои базовые снимки (`npx playwright test --update-snapshots`). Эталон ZIF от этого не зависит: он сравнивает два рендера в одном браузере.

34. **Docker отсутствовал на машине разработки.** `docker-compose.yml`, `docker-compose.prod.yml`, Dockerfile, nginx, Caddy и GitHub Actions написаны, но не запускались. Интеграционные тесты вместо testcontainers идут на встроенном PostgreSQL (`scripts/pg.py`), в CI — на сервисе `postgres:16`.

## Совместная работа и данные

36. **Приглашение привязано к email.** Ссылку принимает только пользователь с тем адресом, на который она выписана; для остальных она выглядит как несуществующая (404). Утёкшая ссылка не даёт доступа постороннему. Ссылка показывается владельцу один раз (в базе только хэш), живёт 7 дней; новое приглашение на тот же адрес отменяет прежнее. Письмо уходит, если настроена почта; ссылку можно передать и вручную.
37. **Роли.** Владелец один и не меняется; владелец назначает «редактор» или «читатель» и убирает участников; участник может выйти сам.
38. **Обновление без перезагрузки — опрос, а не WebSocket.** Клиент раз в 5 секунд запрашивает лёгкую метку ревизии доски (`GET /boards/{id}/revision`: хэш версии доски, числа и времени изменения карточек, пунктов чек-листов, комментариев и ссылок) и перечитывает доску, только когда метка сменилась. Работает за любым прокси без дополнительной настройки; задержка до 5 секунд. Пока своё изменение не подтверждено сервером, метка не принимается, чтобы не затереть оптимистичное состояние. Опрос останавливается, когда вкладка в фоне.
39. **Выгрузка для пользователя:** доска — шаблон JSON, бэкап JSON и таблица CSV для Excel; проект — бэкап JSON; аккаунт — бэкап в профиле. CSV с разделителем «;» и BOM, чтобы кириллица открывалась в Excel без настройки; ячейки, начинающиеся с `= + - @`, экранируются от CSV-инъекции.
40. **База на этом же сервере или внешняя** выбирается в `.env`: профиль `localdb` в `COMPOSE_PROFILES` поднимает контейнер Postgres, без него используется адрес из `KANBANLY_DATABASE_URL`. Для внешней базы нужен `?ssl=require`. Ночные копии делает `deploy/backup-db.sh` для обоих вариантов.
41. **Импорт из прототипа** не знает о конкретном пресете: каждое поле задачи привязывается к тому измерению доски, чьи значения совпали с наибольшим числом задач. Импорт создаёт новую доску рядом, исходная не меняется.
42. **«Оформление» в мастере** переносит из выбранного пресета тему, шрифты и геометрию колонок и карточек. Бейджи, лицевая сторона и виджеты остаются от структуры: они ссылаются на её измерения.
43. **Файлы проекта хранятся в PostgreSQL**, а не на диске или в S3: один сервер без лишних сервисов, файлы попадают в ночную копию базы и в бэкап пользователя (base64). Лимит 25 МБ на файл; при росте объёма данные версий выносятся в объектное хранилище без смены API.
44. **Просмотр без редактирования.** Word и Excel конвертируются в HTML при загрузке (mammoth, openpyxl) и сохраняются вместе с версией, поэтому открываются мгновенно. PDF рисуется pdf.js на canvas: встроенный просмотрщик браузера в песочнице не работает, а на телефонах PDF во фрейме не показывается. Новая версия — это новый файл; старые версии доступны для просмотра и скачивания.
45. **Теги принадлежат проекту.** Один справочник для карточек всех досок и документов; удаление тега снимает его везде. В бэкапе теги хранятся по имени, поэтому восстановление в существующий проект их не дублирует.
46. **Цвет карточки переопределяет токены темы только внутри карточки.** Текст и приглушённый текст подбираются под фон с контрастом не ниже WCAG AA; для любых цветов (в том числе заданных вручную) это гарантирует переход на чистый чёрный или белый.
47. **Блокировка входа — в базе, а не в памяти.** Ограничитель частоты (30 в минуту) защищает от быстрого перебора, а счётчик неудачных входов в таблице пользователей переживает перезапуск и работает при нескольких процессах. После 20 ошибок подряд вход закрыт даже с верным паролем, пока владелец не сбросит пароль по почте или администратор не снимет блокировку.
48. **Администратор — первый пользователь**, далее права выдаёт администратор или команда `python -m app.cli make-admin`. Для не-администратора панель не существует (404), чтобы не раскрывать её наличие.
49. **Импорт доски — на сервере.** CSV и массив задач превращаются в обычный шаблон с карточками и создаются тем же кодом, что и пресет; бэкап восстанавливается кодом бэкапов. Колонки берутся из столбца статуса в порядке появления, вид колонки угадывается по названию («Готово» → done). Повторяющиеся значения становятся измерениями, остальное — полями; апостроф защиты от формул из выгрузки Kanbanly снимается.
50. **Пресет ZIF убран из каталога.** Это шаблон одного заказчика; файл лежит в `docs/reference/` как эталон для тестов и загружается в приложение обычным импортом.
51. **Превью досок — настоящий движок доски.** `GET /boards/{id}/preview` отдаёт настройки и до 6 карточек на колонку; миниатюра грузится, только когда плитка подходит к экрану, и масштабируется под ширину резиновой сетки.
52. **Длинные колонки сворачиваются по тегу.** Больше 20 карточек — сверху первые 5, остальные в раскрывающихся блоках по значению «тега» (по умолчанию измерение фильтр-чипов из шапки доски, иначе теги проекта), карточки без значения — в блоке «Без тега». Карточка попадает только в блок первого значения, чтобы не дублироваться при перетаскивании. Порог, число карточек сверху и источник настраиваются в конструкторе (`layout.column.overflow`). Поиск и фильтры сужают колонку, и найденное показывается без блоков; блок новой карточки раскрывается сам.
53. **Приглашения во входящие.** Приглашение по email или нику, адресованное зарегистрированному пользователю, хранит его id и показывается в «Профиль → Приглашения»; письмо со ссылкой по-прежнему уходит, но для существующего аккаунта оно необязательно. Отказ сохраняется (владелец видит «отклонено»); повторное приглашение заменяет прежнее, поэтому случайный отказ исправляется одной кнопкой. Ник уникален без учёта регистра, 3–32 символа латиницей.
54. **Исполнитель — отдельное поле карточки**, а не измерение: он связан с аккаунтом, проверяется по участникам проекта и снимается при выходе из проекта. Измерения типа «user» из шаблонов остаются как были (это просто список имён). В бэкапе исполнитель хранится по email и восстанавливается, только если такой человек — участник целевого проекта.
55. **Администратор скачивает бэкапы чужих досок и аккаунтов** (меняет п. 48 о полной закрытости). Нужен для поддержки и резервного копирования на маленьком сервере без отдельного DBA. Просмотра чужих досок в интерфейсе нет; каждая выгрузка пишется в журнал безопасности, который видят все администраторы.
56. **Картинки Word не вшиваются в HTML просмотра.** Раньше документ со скриншотами превращался в HTML с base64-картинками и упирался в лимит просмотра 5 МБ («файл слишком большой или сложный»). Теперь в HTML остаётся ссылка на `/documents/{id}/versions/{n}/images/{i}`, а картинка берётся из самого docx по SHA-256 (в базе не дублируется), тип проверяется по содержимому, отдаётся с `nosniff` и CSP `sandbox`. Документы, загруженные раньше, пересобираются при первом открытии. EMF/WMF браузер не показывает — вместо них подпись.
57. **Оглавление в документах работает.** Метки разделов из Word (закладки, сноски) получают префикс `doc-` (mammoth `id_prefix`), заголовки Markdown — метку в стиле GitHub (`doc-механики-боя`). Обе очистки HTML пропускают только `id` с этим префиксом и ссылки `#doc-…`: метка документа не может перекрыть элемент страницы. Щелчок по внутренней ссылке прокручивает блок документа, не открывая вкладку и не меняя адрес. Просмотры Word прежнего формата пересобираются при открытии.
58. **Содержание документа строится автоматически.** Word и Markdown — по заголовкам отрисованного документа (а не по готовому оглавлению: оно есть не всегда, а заголовки — почти всегда), PDF — по закладкам файла через pdf.js `getOutline`. На широком экране это закреплённая колонка слева, на узком — закреплённая кнопка над документом; текущий раздел подсвечивается при прокрутке. Если разделов меньше двух, панель не показывается.
59. **index.html не кэшируется** (`Cache-Control: no-cache`): после обновления сервера браузер сразу получает новый интерфейс. Файлы из `/assets/` с хэшем в имени по-прежнему кэшируются на год.
60. **Аватар кадрируется в браузере.** Пользователь выбирает любую картинку, двигает и масштабирует её под круг; на сервер уходит только готовый квадрат 256×256 (WebP или PNG), оригинал фото с компьютера не загружается. Сервер принимает только PNG, JPEG и WebP до 1 МБ (тип — по содержимому), хранит аватар в отдельной таблице (users читается на каждом запросе) и отдаёт его с `nosniff` и CSP `sandbox` только коллегам по проекту и администратору. Номер версии в адресе картинки сбрасывает кэш при смене фото.
61. **Статус как в мессенджерах.** Онлайн/офлайн — по последней активности сеанса (окно 3 минуты; открытое приложение опрашивает сервер раз в минуту), «занят» и «невидимка» выбираются вручную. Занятый, но неактивный пользователь показывается офлайн; невидимка — всегда офлайн.
