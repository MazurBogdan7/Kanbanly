# Безопасность

## Что защищаем

Учётные записи, содержимое проектов и бэкапы. Основные угрозы: доступ к чужим данным, захват сессии, вредоносные шаблоны и бэкапы, выполнение пользовательского кода в браузере, утечка секретов через логи.

## Модель угроз

| Угроза | Защита | Проверка |
|---|---|---|
| Чтение или запись чужих данных | единый слой `repositories/access.py`; чужое, удалённое и несуществующее неотличимы (404) | `tests/security/test_isolation.py`: каждый маршрут с id из OpenAPI |
| Перебор паролей | лимит 30 попыток в минуту на IP+email; после 20 неудачных входов подряд аккаунт блокируется (хранится в БД, переживает перезапуск) до сброса пароля по почте или разблокировки администратором | `test_web.py`, `test_core.py`, `test_workspace.py`, e2e |
| Вредоносный файл в документах проекта | тип определяется по содержимому, а не по имени или Content-Type; встроенно отдаются только картинки, остальное — вложением с `application/octet-stream`, `nosniff` и CSP `sandbox`; Word и Excel превращаются в HTML на сервере (nh3) и ещё раз чистятся DOMPurify; внешние картинки вырезаются; zip-бомба не распаковывается; PDF рисует pdf.js без `eval` | `test_workspace.py`, `workspace.test.ts`, e2e |
| Злоупотребление правами администратора | администратор может скачать бэкап чужой доски или аккаунта (резервное копирование и поддержка по решению владельца сервиса); каждая выгрузка пишется в журнал безопасности с id доски или пользователя и IP; просматривать чужие доски в интерфейсе он не может; для не-админа маршруты `/admin` отвечают 404 | `test_admin_downloads_foreign_boards`, `test_isolation.py`, e2e |
| Приглашение получает посторонний | приглашение адресовано конкретному пользователю (id) или email; принять или отклонить по id может только адресат, остальным — 404; ссылка из письма работает только для владельца email | `test_invite_by_nick_lands_in_inbox`, `test_members.py` |
| Исполнитель вне проекта | исполнителем можно назначить только участника проекта (422 иначе); при выходе из проекта назначения снимаются | `test_assignee_must_be_member` |
| Слабые пароли | ≥ 10 символов, список 100 тыс. утёкших паролей, Argon2id | `test_auth.py` |
| Угон сессии | токен 256 бит, в БД только SHA-256; `httpOnly`, `Secure`, `SameSite=Lax`; ротация при входе; 7 дней бездействия; выход на всех устройствах | `test_auth.py`, e2e |
| CSRF | double submit для всех изменяющих запросов | `test_every_mutating_route_requires_csrf` |
| XSS | React экранирует текст; Markdown: сырой HTML экранируется, затем DOMPurify с белым списком тегов; `dangerouslySetInnerHTML` запрещён линтером вне одного файла; CSP без `unsafe-inline` для скриптов | `lib.test.ts`, `quality.spec.ts` |
| Инъекция стилей через шаблон | цвета по регулярке, URL только `https` без спецсимволов, шрифты из белого списка; произвольного CSS нет | `test_template_schema.py`, `engine.test.ts` |
| Посторонний по утёкшей ссылке-приглашению | приглашение принимает только владелец указанного email, ссылка одноразовая, 7 дней, в базе хэш | `tests/api/test_members.py` |
| Повышение прав участником | роли меняет только владелец, роль владельца неизменна | `test_roles_and_leaving` |
| Открытый редирект после входа | возврат только на локальный путь (`safeNext`) | `pages.test.tsx` |
| Формулы в выгрузке CSV | ячейки с `= + - @` экранируются | `test_csv_export` |
| Вредоносный JSON | лимиты размера, глубины, числа сущностей и длины строк; неизвестные поля и `__proto__` отбрасываются | `test_template_schema.py`, `test_backup.py` |
| Zip-бомба в `.json.gz` | распаковка останавливается на лимите | `test_zip_bomb_rejected` |
| Подмена бэкапа | SHA-256 на содержимое, AES-256-GCM с параметрами KDF в AAD | `test_backup.py` |
| Чужой бэкап пишет в чужой аккаунт | все id пересоздаются, владелец — текущий пользователь | `test_foreign_backup_lands_in_own_account` |
| Утечка секретов в логи | фильтр логгера, письма в лог не пишутся | `test_secrets_never_reach_logs` |
| Секреты в бэкапе | экспорт формируется явным перечнем полей | `test_backup_contains_no_secrets` |
| Отказ обслуживания большим телом | общий лимит тела запроса | `test_oversized_body_rejected` |
| Отказ обслуживания регулярным выражением | запрет вложенных квантификаторов, лимиты длины | `test_catastrophic_regex_rejected` |
| Падение БД на недопустимом тексте | NUL и одиночные суррогаты отвергаются на входе | `test_unstorable_text_rejected_in_json_body` |

## Секреты

- Только из окружения; `.env` в `.gitignore`, образец — `.env.example`.
- В `prod` приложение не стартует с ключом по умолчанию, с заглушками из `.env.production.example` и с `KANBANLY_COOKIE_SECURE=false`.
- Секрет TOTP зашифрован AES-256-GCM; резервные коды, токены сессий и сброса пароля хранятся только хэшем.
- Ссылка сброса действует 30 минут, одноразовая, завершает все сессии.

## Заголовки

`Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`; `Strict-Transport-Security` в `prod`. Ответы API не кэшируются.

## Журнал аудита

Вход, регистрация, смена и сброс пароля, 2FA, импорт и экспорт, удаление доски и проекта, удаление аккаунта. Запись об удалении аккаунта обезличена.

## Известные ограничения

- Rate limit живёт в памяти одного процесса (см. DECISIONS, п. 17).
- Защита от ReDoS эвристическая (п. 21).
- Регистрация раскрывает, занят ли email (п. 18).
- Подтверждение email при регистрации не реализовано: ТЗ его не требует.
- IP клиента берётся из `X-Forwarded-For`, которому `api` доверяет полностью (`--forwarded-allow-ips=*`). Это безопасно, пока порт `api` не опубликован: в Compose он доступен только внутри сети.
