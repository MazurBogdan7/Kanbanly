# Архитектура

## Главная идея

Конфигурация доски — одна структура (`BoardConfig`), которая живёт в трёх местах и не меняет формы:

```
шаблон (JSON-файл, пресет) ──┐
конструктор (черновик)     ──┼──► движок рендера (BoardCanvas)
доска из БД (BoardOut)     ──┘
```

Движок работает с локальными ключами (`epic`, `done`), а не с UUID. Поэтому живая доска, live-preview конструктора и миниатюра в галерее — один и тот же компонент с разными данными.

Источник правды — Pydantic-модели в `backend/app/schemas/template.py`. Из них генерируются JSON Schema (`docs/schemas`) и TS-типы (`frontend/src/lib/api/schema.gen.ts`).

## Backend

| Слой | Каталог | Ответственность |
|---|---|---|
| API | `app/api` | HTTP, куки, ETag; без бизнес-логики |
| Доступ | `app/repositories/access.py` | единственный путь к ресурсам: проверка членства и роли, чужое = 404 |
| Сервисы | `app/services` | карточки, конфигурация, шаблоны, бэкап, авторизация |
| Модели | `app/models` | таблицы SQLAlchemy |
| Схемы | `app/schemas` | форматы JSON и REST |
| Инфраструктура | `app/core` | настройки, БД, ошибки, логирование, middleware, rate limit |

Транзакция: одна на запрос, зависимость `Db` выполняет commit до отправки ответа (`scope="function"`) и rollback при любой ошибке. На этом держится атомарность импорта.

### Запись структуры

`services/board_config.py::apply_config` — единственный путь записи колонок, измерений, полей и представлений. Его используют создание из шаблона, конструктор (`PUT /boards/{id}/config`), частичный импорт и восстановление бэкапа. Сопоставление идёт по ключам: строки обновляются на месте, карточки сохраняют значения. Карточки удалённой колонки переходят в первую колонку.

Настройки оформления лежат в `Board.settings` (JSONB, модель `BoardSettings`), структура — в нормальных таблицах: по ней фильтруют и считают прогресс.

### Роли измерений

Роли (`accent`, `badge`, `progress`…) вычисляются из раскладки, а не хранятся отдельно: виджет и роль не могут разойтись. Тогда выключение роли — это удаление виджета. Роли, объявленные в шаблоне, разворачиваются в раскладку при импорте.

### Порядок

Fractional indexing: `services/fractional.py` — порт `fractional-indexing`, который использует фронт. Перемещение меняет ключ одной карточки. В PostgreSQL столбец `position` с `COLLATE "C"`, иначе локаль БД сломает порядок.

### Бэкап

Экспорт потоковый: доски пишутся по одной, сессия очищается после каждой. Ключи `data` идут по алфавиту, поэтому поток совпадает с каноническим JSON и контрольная сумма считается на лету; на импорте она сверяется с канонической сериализацией.

## Frontend

```
src/features/boards/engine   движок: theme, model, BoardCanvas, KanbanView, TableView, CardFace, HeaderWidgets
src/features/settings        конструктор: черновик с undo/redo, вкладки, профиль
src/features/templates       галерея, импорт с превью, живые миниатюры
src/lib/api                  клиент (CSRF, ETag, ошибки), сгенерированные типы
src/design-system            токены приложения и белый список шрифтов
```

Тема доски применяется CSS-переменными на корне `.kb-board` (`--t-accent`, `--ty-card-title-font`). Цвет в настройках — hex или ссылка на токен, которая становится `var(--t-…)`, поэтому смена токена перекрашивает всё сразу. Значения проходят проверку на сервере и повторно в `resolveColor`/`backgroundCss`.

Серверное состояние — TanStack Query с оптимистичными обновлениями и откатом. Локальное — Zustand: черновик конструктора, стек undo, toasts, язык.

Производительность: карточки обёрнуты в `memo`, вне экрана браузер пропускает вёрстку через `content-visibility: auto`.

## Тесты

| Уровень | Где |
|---|---|
| Unit, API, безопасность, свойства | `backend/tests` |
| Компоненты и экраны | `frontend/tests/unit` |
| E2E, эталон ZIF, axe, производительность | `frontend/tests/e2e` |
| Визуальные снимки | `frontend/tests/visual` |

Проверки изоляции и CSRF строят список маршрутов из OpenAPI: новый эндпоинт попадает в них автоматически.
